The canonical, production-grade technical product description for AISSC (operating under the commercial identity AISSC-Automated-Online Empire )
 is defined under the Architect’s Mandate as follows:
"Electron-Online is a fully autonomous, self-bootstrapping, self-learning, and auto-improving multi-agent enterprise system governed by a three-manager OpenClaw core (Sheryl, Krieger, and Malory)
. The system retrofits the NEXUS Systems Framework to function as an enclosed, structured cognitive 'Hive Mind' accessed by all agents via a Model Context Protocol (MCP) server to systematically eliminate technical drift
.
By recursively decomposing complex, long-term business goals into manageable, machine-readable Markdown files, the system processes tasks in scenario-specific execution phases
. All tactical AI/ML processing operations are assigned to a roster of 284+ specialized, deliverable-matched Agency-Agents
. These agents are fired off on-demand via a Google Cloud Pub/Sub event bus to run ephemerally inside stateless, containerized Google Cloud Run runtimes configured under Spin-Up-And-Die (SUAD) scale-to-zero physics
. This cost-saving architecture eliminates persistent virtual private servers (VPS) and cuts infrastructure idle costs entirely, achieving sub-2-second cold-start deployments
.
An AI Automation Orchestrator Agent dynamically manages execution priorities, scheduling tasks into planned queues based on a 30+ factor ROI-routing analysis
. This routing engine maximizes efficiency by routing simple tasks to single specialized SUAD workers, intermediate actions to NEXUS-Micro multi-agent teams, and the most complex operations to hybrid NEXUS-Sprint pipelines
. These hybrid pipelines deploy custom containerized workspaces, such as pre-configured LobeHub group collaboration teams, while caching all strategic designs, schemas, and execution states within the OpenViking RAG database for instantaneous, amnesia-free recall
."

Ingress and Strategic Intake: Sheryl parses incoming commands (e.g., via Telegram Webhook) into validated JSON schemas and registers the task with the Senior Project Manager
.
Phase 1.5 State Anchoring: The system executes generate-nexus-docs.mjs --mode micro to generate the active Markdown state tracking files, preventing loose files or lost states
.
30-Factor Queue Scheduling: The AI Automation Orchestrator calculates RICE prioritization, analyzes target SLA requirements, and enqueues the tasks on Google Cloud Tasks to protect free-tier quotas and prevent container concurrency bottlenecks
.
SUAD Activation: Google Cloud Tasks boots a targeted GCP Cloud Run service account
. The container mounts the shared OpenViking RAG database via GCS FUSE, pulls environment keys dynamically from Google Secret Manager, and completes its discrete task within a brief 2-minute request window
.
Evidence QA Validation: The developer's output is routed to the Evidence Collector, which captures multiple responsive viewport screenshots to verify implementation against the original Markdown requirements
.
Hardening and Verification: The Reality Checker evaluates the code. Defaulting to a strict verdict of "NEEDS WORK", it checks for idempotent execution, dead-letter queues, and sequence IDs to ensure production readiness before creating a signed handoffs/qa-pass.md certificate
.
Pub/Sub State Sync: The completed task publishes its results to the Google Cloud Pub/Sub event bus, syncing the output back to your persistent Markdown documents, alerting Sheryl, and shutting down the container to maintain a $0.00 infrastructure idle-cost baseline
.
